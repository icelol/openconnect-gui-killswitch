# OpenConnect GUI + Kill Switch

**1.1.3 — индикатор службы и диагностика зависаний.** Индикатор **«Служба»**
проверяет ответ каждые 2 секунды и показывает версию и задержку. Состояние
блокировки и этап VPN видны отдельно. **«Диагностика службы»** читает правила
PF локально, без Терминала и дополнительного пароля администратора.

Ошибка входа больше не перекрывает управление. Отдельные таймеры: 30 секунд
для соединения с сервером, 90 секунд для ответа авторизации после отправки
формы, 60 секунд для туннеля, 120 секунд для ввода каждой формы.

Если шлюз зависает до
формы логина, в настройках его профиля доступны **«Совместимость: только TLS 1.2»**
и **«Вход Cisco без XML POST»**. Параметры выключены по умолчанию и действуют
только для этого профиля. Сертификат и имя сервера продолжают проверяться;
TLS 1.0/1.1 и небезопасные шифры не включаются.

Ход подключения теперь виден в **View log**. Зависшая попытка до входа ограничена
тайм-аутом; ожидание ввода пароля не прерывается этим тайм-аутом.

В версии **1.1.1** есть отдельная кнопка **«Снять блокировку OpenConnect»**.
Она отправляет OFF даже после ошибки включения/восстановления или при уже
выключенном переключателе. Ошибка восстановления PF больше не останавливает
службу и не лишает возможности выключения. Программа снимает свои правила;
PF может оставаться включённым для других приложений.

Без запроса пароля администратора, через установленную службу:

```sh
/Applications/OpenConnect-GUI-KillSwitch.app/Contents/MacOS/OpenConnect-GUI-KillSwitch --service-disable
```

Успех выводится после подтверждения OFF службой. Если служба недоступна,
используйте `Recover Kill Switch.command` из DMG с локальным подтверждением
пароля администратора.

**Клиент OpenConnect для macOS с системным kill switch, независимым от Connect и Disconnect.**

[English](README.md) · [Релизы](https://github.com/icelol/openconnect-gui-killswitch/releases) · [Архитектура](docs/macos-killswitch.md)

Укажите собственный VPN-сервер и протокол. В приложении нет заранее настроенной
организации, учётной записи, адреса сервера, внутреннего Git-сервера или паролей.

## Возможности

- Один переключатель блокирует трафик вне VPN, установленного этим клиентом.
- При включённой блокировке кнопка Connect остаётся доступной.
- Можно выбирать совместимые серверы и менять шлюз без временного открытия
  обычного доступа в интернет.
- Список протоколов получает сама libOpenConnect: AnyConnect/ocserv, Juniper,
  Pulse/Ivanti, GlobalProtect, F5, Fortinet и Array, если они есть в этой библиотеке.
- Системная служба управляет VPN и PF; интерфейс работает от обычного пользователя.
- Закрытие окна, Disconnect и обрыв VPN не снимают включённую блокировку.
- В установщике есть полная очистка, а в DMG — отдельные очистка и восстановление.

OpenConnect работает с SSL VPN. Для OpenVPN `.ovpn` и WireGuard нужны другие
движки, их профили здесь не поддерживаются. Служба поддерживает прямое подключение,
запросы логина/пароля и штатное доверие TLS. Произвольные скрипты, прокси профиля,
файлы клиентских сертификатов и вход SSO через браузер в службе пока не реализованы.

## Установка и работа

Готовая сборка рассчитана на **Apple Silicon и macOS 27 и новее**. Homebrew и Python
на компьютере сотрудника не нужны.

1. Скачайте PKG из [релизов](https://github.com/icelol/openconnect-gui-killswitch/releases).
2. Выполните обычную установку. На новом компьютере блокировка изначально выключена.
3. Создайте свой профиль: адрес шлюза, подходящий протокол и при необходимости логин.
4. При необходимости включите **«Блокировать интернет без VPN»**, затем нажмите Connect.
5. Введите пароль VPN локально. Для обычного доступа к сети без этого VPN вручную
   выключите переключатель.

| Состояние | Доступ к сети |
| --- | --- |
| Переключатель выключен | Обычная сеть и интернет |
| Переключатель включён, VPN отключён | Обычный интернет и LAN заблокированы; подключение к VPN разрешено |
| Переключатель включён, VPN подключён | Трафик через выбранный VPN этого клиента |
| VPN отключён или оборвался | Блокировка сохраняется |
| Окно закрыто | Служба и выбранная защита продолжают работать |

Переключатель работает и без готового профиля: блокирует обычную сеть до
подключения VPN или явного выключения. Обновление завершает текущую VPN-сессию
этого клиента и сохраняет выбранное состояние защиты. После обновления подключитесь заново.

Служебные исключения: loopback, DHCP, IPv6 NDP и соединения root к IP/портам
выбранного шлюза. Для нового домена служба временно разрешает **DNS только для root
и только к DNS-серверам macOS**, получает A/AAAA выбранного шлюза и удаляет исключение
вместе с его состояниями PF. Постоянного разрешения общего DNS и встроенного
стороннего DNS-провайдера нет.

Подпись приложения — **локальная ad-hoc**. PKG не имеет Developer ID и notarization.
Это общественный проект, а не управляемый через MDM Always On VPN. Защита не
рассчитана на противодействие администратору с root.

## Полная очистка и восстановление

В том же установщике выберите **«Полностью очистить OpenConnect»**. Удаляются
приложение, служба, автозапуск, настройки, кэши, журналы и собственные правила PF.
Сохранённые профили удаляются. Известные тестовые копии приложения переносятся в
Корзину. Другие VPN и чужие правила PF сохраняются.

В DMG есть `Clean OpenConnect.command` и `Recover Kill Switch.command`.
Восстановление снимает собственную блокировку и перезапускает службу с выключенным
переключателем, сохраняя приложение и профили.

Из исходников:

```sh
./scripts/clean-macos-all.sh --dry-run
./scripts/clean-macos-all.sh
# Или восстановить сеть без удаления приложения:
./scripts/recover-killswitch.sh
```

Пароль администратора macOS вводится только локально в системном запросе.

## Сборка и проверки

Нужны Mac с Apple Silicon, Xcode Command Line Tools, Homebrew и Python 3:

```sh
brew install cmake ninja pkg-config qtbase qtsvg qtscxml openconnect gnutls spdlog ca-certificates
export PATH="$(brew --prefix qtbase)/bin:$PATH"
./scripts/build-macos.sh
```

Скрипт запускает тесты, проверяет библиотеки, фактический минимум macOS и подписи,
затем создаёт PKG, DMG и переносимые SHA-256 в `dist/`. Сборка не устанавливает
приложение и не меняет действующую сеть. Промежуточный GUI хранится в скрытой
`.app-build.noindex`, чтобы не создавать дубли в поиске. Хранилище CA берётся из
исходного пакета доверенных центров, без локально добавленных корней.

```sh
python3 scripts/validate-release.py
ctest --test-dir build --output-on-failure
```

PF и VPN в тестах подменяются; настоящий `pfctl -n` проверяет синтаксис правил.
Проверяются первое подключение, повторные команды, отмена, смена шлюза, удаление
временного DNS, проверка протоколов и UID локального IPC, независимость переключателя.
Совместимость конкретного сервера, сон, смена сети и перезагрузка требуют испытаний
на Mac. Наличие протокола в списке не означает, что все серверы этого производителя
были проверены в реальном подключении.
