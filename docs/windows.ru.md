# Установка и восстановление в Windows

[English](windows.md) · [Архитектура](windows-architecture.md)

В установщик x64 входят интерфейс, libOpenConnect, публичные корневые сертификаты
и Wintun. MSYS2, Python и отдельный OpenConnect на компьютере сотрудника не нужны.
Клиент работает с протоколами OpenConnect. Профили OpenVPN `.ovpn` и WireGuard
он не импортирует.

1. Скачайте установщик Windows x64 из Releases проекта.
2. Запустите EXE и подтвердите запрос администратора Windows. Перед обновлением
   закройте старое окно клиента. Служба устанавливается в Program Files и запускается
   вместе с Windows. Автозапуск самого окна выбирается отдельно в установщике.
3. Добавьте свой адрес шлюза и выберите его протокол. Для Cisco AnyConnect или
   ocserv нужен **Cisco AnyConnect or OpenConnect**. Логин и пароль запрашиваются
   при подключении.
4. Включите **«Блокировать интернет без VPN»**, когда нужна защита. Обычный интернет
   и LAN будут заблокированы; кнопки Connect и Disconnect работают независимо.
5. Чтобы вернуть обычный доступ, вручную выключите переключатель. Закрытие окна,
   отключение VPN и остановка службы не означают снятия блокировки.

На новом компьютере защита изначально выключена. Обновление сохраняет выбранное
состояние и завершает старую VPN-сессию — после обновления подключитесь заново.
В окне отдельно видны подтверждённое состояние защиты, ответ службы, её версия,
задержка и этап подключения. Диагностика читает локальные сведения без их отправки.

Установщик не подписан сертификатом издателя. Сборка предназначена для Windows x64;
версии ARM64 и 32-bit не выпускаются.

## Снятие блокировки и восстановление

Выключите переключатель либо нажмите **«Снять блокировку OpenConnect»**. Пока
служба отвечает, выбранному пользователю не нужен повторный пароль администратора.

Команда PowerShell через работающую службу:

```powershell
& "$env:ProgramFiles\OpenConnect-GUI-KillSwitch\openconnect-gui.exe" --service-disable
```

Если служба недоступна, откройте PowerShell **от имени администратора**:

```powershell
& "$env:ProgramFiles\OpenConnect-GUI-KillSwitch\openconnect-gui.exe" --recover-killswitch
```

Восстановление останавливает эту службу, удаляет правила WFP проекта и снова
запускает службу с сохранённым OFF. Профили приложения и чужие правила firewall
сохраняются. Общего сброса Windows Firewall нет.

Для удаления используйте **«Установленные приложения»** Windows или пункт **Remove**
в папке клиента в меню «Пуск». Удаление проверяет снятие собственных сетевых
правил и только затем убирает программу и защищённые данные службы.

## Сборка и проверки

Сборка выполняется в оболочке MSYS2 **UCRT64** с пакетами из
`.github/workflows/windows.yml`:

```sh
sh scripts/build-windows.sh
```

Скрипт проверяет контрольную сумму исходников OpenConnect, собирает библиотеку,
интерфейс и службу, запускает тесты DNS, добавляет зависимости и их лицензии,
проверяет архитектуру PE и запуск GUI без повышения прав. Результат — установщик
NSIS, SHA-256 и соответствующие изменённые исходники библиотеки LGPL.
`DEPENDENCIES.json` содержит версии пакетов и хеши поставляемых EXE/DLL.

`tests/windows_smoke.py` предназначен **только для временной Windows-машины GitHub
Actions**. Он меняет её сетевые правила и отказывается запускаться на обычном
компьютере. Проверяются установленная программа, подлинность службы, неверные
команды IPC, текущие и новые соединения, ON/OFF, локальная авторизация TLS/CSTP и
обмен пакетами через настоящий Wintun, перезапуск, обновление, восстановление и
удаление. Временный тестовый CA добавляется только в установленную копию на runner
и удаляется после проверки; в дистрибутив он не попадает.

Проверка на Windows Server 2022 в CI не заменяет проверку на ноутбуках Windows 10/11.
Перед развёртыванием проверьте реальный VPN-шлюз, DTLS/UDP, сон, смену Wi-Fi/Ethernet,
перезагрузку и совместимость с защитным ПО. Если у runner нет внешнего IPv6,
соответствующая сетевая проверка помечается как недоступная.
